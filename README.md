# Expense Report Automation Demo

A small, Windows-friendly Python tool that turns a folder of monthly expense CSV files into one reviewed Excel workbook, and **keeps every bad row visible, with its original input, instead of silently fixing or dropping it**.

> **Synthetic data only.** Every CSV in `input/` is fictional and is generated by `sample_data/generate_sample_expense_data.py` (fixed random seed). No real employer, customer or personal data, and no credentials, are used or required.

## The problem it solves

Month-end expense reporting is usually: collect several CSVs, paste them together in Excel, eyeball for bad dates and amounts, rebuild the pivot tables. It is slow, and errors are hard to audit afterwards ("which row was excluded, and why?").

This tool replaces that with a repeatable run that produces:

- totals by office, department and expense type, **from valid rows only**;
- an `Error_Report` sheet listing every rejected row with the reason(s) **and the original, untouched input values**;
- a run log that states what was processed, skipped or overwritten.

## Flow at a glance

```text
input/expense_<office>_<yyyy-mm>.csv  (one file per office)
   |
   |  1. File checks    file name pattern, single report month, required columns
   |  2. Row validation each row checked; original values kept next to normalized values
   |  3. Aggregation    valid rows only -> office / department / expense type
   v
output/Expense_Report_<yyyy-mm>.xlsx   +   output/process_log.txt
```

## What happens on bad data

| Situation | Behavior | Exit code |
| --- | --- | --- |
| Row fails any validation rule | Row is kept in `Raw_Data` and `Error_Report` with all errors in `ErrorType`; **excluded from every total** | 0 |
| Row `Date` is valid but not in the month from the file name | Row is flagged `Mismatched Report Month` and excluded from totals | 0 |
| File name does not match the pattern | File skipped, noted in the log | 0 |
| Required column missing | File skipped, missing columns named in the log | 0 |
| File cannot be read as CSV | File skipped, reason in the log | 0 |
| Files for more than one report month | Run aborted, **no workbook written**, log explains | 1 |
| No CSV files in the input folder (or folder missing) | No workbook written, log says so | 0 |
| No file name is valid | No workbook written (log lists skipped files) | 0 |
| An existing `Expense_Report_<yyyy-mm>.xlsx` is present | Overwritten; stated in the log (`Existing output overwritten: Yes`) | 0 |

Note the exit code is 0 for skipped files and empty input. Check `process_log.txt` (`File-level warnings/errors`) in scheduled runs.

## Quick start

Requires Python 3.10+ (CI covers 3.10 to 3.13).

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

python sample_data\generate_sample_expense_data.py   # (re)creates fictional input\*.csv
python src\generate_expense_report.py                # writes output\Expense_Report_2026-01.xlsx and output\process_log.txt
```

Custom folders: `python src\generate_expense_report.py --input-dir <dir> --output-dir <dir>`

On macOS/Linux use `source .venv/bin/activate` and forward slashes.

### Run the tests

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

GitHub Actions (`.github/workflows/ci.yml`) runs the same `pytest` on pull requests and on pushes to every branch except `main`.

## Input format

File name: `expense_<office>_<yyyy-mm>.csv` (case-insensitive). Office tokens: `singapore`, `tokyo`, `london`, `new_york`. All files in one run must share the same month.

Required columns (UTF-8, with or without BOM):

```text
Date, Office, Department, Employee, ExpenseType, Amount, Currency, Description
```

Accepted values: `Date` strict `YYYY-MM-DD`; `Amount` plain number, optional leading `$` and thousands separators (parentheses and text prefixes such as `USD 120.50` are rejected); `Currency` `USD` only; Office / Department (`IT, Admin, Finance, Sales, Operations, HR`) / ExpenseType (`Travel, Meal, Software, Office Supplies, Training, Telecom, Other`) are matched case-insensitively after trimming whitespace.

## Validation rules

Per row, all failures are collected in `ErrorType`, separated by ` | `:

- Missing Date / Invalid Date / **Mismatched Report Month**
- Missing Office / Invalid Office / Mismatched Office (must equal the office in the file name)
- Missing Department / Invalid Department
- Missing Employee
- Missing ExpenseType / Invalid ExpenseType
- Invalid Amount / Non-positive Amount
- Missing Currency / Unsupported Currency
- Missing Description

`Mismatched Report Month` is only reported when `Date` is a valid date; an invalid or missing date reports only its own error.

## Original vs. normalized values

`Raw_Data` and `Error_Report` carry two sets of columns:

- `Date, Office, ..., Amount, Currency, Description`: **normalized** values (trimmed, canonical spelling such as `singapore` -> `Singapore`, `$1,200.50` -> `1200.5`). Aggregation uses only these, and only for valid rows. An unparseable `Amount` is blank here.
- `Original_Date, Original_Office, ..., Original_Description`: the text exactly as read from the CSV (no trimming or case change), for audit.

## Output workbook

`output/Expense_Report_<yyyy-mm>.xlsx`, plus `output/process_log.txt`.

| Sheet | Content |
| --- | --- |
| Summary | Report month, file/record counts, total amount, top office / department / expense type, generation time |
| By_Office, By_Department, By_ExpenseType | Total amount and record count per group, valid rows only |
| Raw_Data | Every row from processed files: source file, row number, normalized values, `IsValid`, `ErrorType`, `Original_*` |
| Error_Report | Invalid rows only, same columns minus `IsValid` |
| Run_Log | Copy of the process log |

Totals are rounded to 2 decimals; amount columns use `#,##0.00`; header row is bold and frozen.

Text that comes from the CSV is never written as a formula: a value such as `=1+1` is stored as plain text with its characters unchanged, so the workbook contains no formula cells (checked on all 7 sheets).

## What this project demonstrates

Implemented and tested here: multi-file CSV consolidation, strict row validation with an audit trail, valid-only reconciled summaries, a formatted multi-sheet Excel deliverable, a run log, a CLI with configurable folders, and CI.

Adjacent work this structure could be adapted to (**not implemented in this repository**): other file layouts or validation rules, other currencies, additional summary sheets, scheduled execution, and a different output format. Each of these would be a scoped change, not a configuration switch.

## Known limitations

- USD only; no currency conversion.
- Office, department and expense-type lists are constants in the source (`src/generate_expense_report.py`), not configuration.
- One report month per run; mixed months abort.
- Skipped files and empty input still exit with code 0; only the multiple-months abort returns 1.
- `Original_*` values are kept for the 8 input columns; there is no cross-run history or duplicate-row detection.
- Invalid rows are excluded, never auto-corrected; there is no approval or re-submission workflow.
- Tested on the pinned pandas/openpyxl versions via CI on Linux; Windows is a supported target but not part of CI.
- The "no formula cells" guarantee is tested by reloading the saved `.xlsx` with openpyxl and by scanning the sheet XML for formula elements. It has not been checked by opening the workbook in desktop Excel on Windows. Editing a text cell in Excel (for example F2 then Enter) can make Excel re-interpret it, and re-exporting the sheet to CSV does not add protection.
- No GUI, database, email sending, or BI integration.
